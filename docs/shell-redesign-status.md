## Lock brightness recovery

If the device is reachable over SSH and its panel is dark after a failed lock attempt, check the secure lock state and restore the known maximum raw setpoint only if needed:

```sh
printf '2047\n' | ssh -F /dev/null -o BatchMode=yes -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR -o ConnectTimeout=4 moarchy@172.16.42.1 'sudo -n /usr/bin/tee /sys/devices/platform/soc@0/4ac0000.geniqup/4a84000.i2c/i2c-0/0-0036/backlight/ktd3136-backlight/brightness >/dev/null'
```

`2047` is the measured known-visible raw setpoint. This writes only the backlight brightness attribute; it does not change DPMS or display-link state. The lock helper is being changed to accept a validated restore override, because the current kernel's LM3697 write mapping can make an intermediate saved raw setpoint produce an unexpected physical brightness. A separately triggered crash-watchdog restore path has not been observed.
